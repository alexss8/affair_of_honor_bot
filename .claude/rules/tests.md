# Тесты

**Важно при написании новых тестов:** В `aiogram 3` глобальный объект `router` хранит ссылку `_parent_router`. В фикстурах тестов после `yield` обязательно сбрасывайте привязку (`router._parent_router = None`).

## Структура тестов (`tests/`)
- `test_unit.py` — логика раундов, отмена боя (`/cancel`), прерывание всех боёв при остановке, снимок боёв в SQLite и их восстановление в движке, работа кэша и рейтинга SQLite, склонения и текст справки, один открытый вызов от игрока в чате (бронь до отправки карточки).
- `test_scenarios.py` — сквозные сценарии через `aiogram.Dispatcher` (вызов, отзыв вызова, сдача, отмена, двойное нажатие «Принять», ник инициатора из кэша, пауза карточек при остановке и продолжение боя после рестарта, фолбэк «бой прерван», второй и одновременный `/duel` при открытом вызове, вызов истекает сам — и после рестарта).
- `test_tg_errors.py` — проверка контракта `safe_api.py` на все ошибки Telegram API и очистка зависших сессий при удалении сообщения админом.
- `test_health.py` — проверка метрик БД и прав доступа к админ-команде `/status`; лог для теста пишется настоящим форматтером из `bot/logger.py`.
- `test_log_context.py` — контекст в логах: запись внутри апдейта и ошибка обработчика несут `chat=<id>`, после апдейта контекст не протекает (`chat=-`).
- `test_alerts.py` — ограничение частоты алертов админу: ключ «одинаковой» ошибки, интервал и счётчик повторов, обработчик ошибок шлёт одинаковую ошибку раз за интервал.
- `test_unicode.py` — любые символы в именах (кириллица, эмодзи, RTL, иероглифы, SQL и HTML в тексте) проходят через рейтинг, кэш ников и снимок боёв без искажений; битый символ (одиночный суррогат) не роняет запись и не губит пачку фоновой записи ников.
- `helpers.py` — общие хелперы тестов: `build_dispatcher`, `make_invite`, апдейты, готовые `callback_data` (`ACCEPT`, `ATTACK_TOP`, ...), подменённые часы лимитера `FakeClock` и `max_in_window`.
- `test_setup_env.py` — мастер `scripts/setup_env.py` записывает в `.env` все настройки (сверяется с `.env.example`).
- `test_setup_dev.py` — `scripts/setup_dev.py`: отказ на Python ниже 3.12, создание `.venv` и установка зависимостей (пустой файл зависимостей, без сети), повторный запуск не пересоздаёт окружение, `--recreate` пересоздаёт и не удаляет папку без `pyvenv.cfg`.
- `test_check.py` — `scripts/check.py`: все шаги прошли — код 0 и только отметки в консоли; упавший шаг — код не 0, его хвост в консоли, полный вывод всех шагов в логе; состав шагов по умолчанию.
- `test_config.py` — проверка `.env` при старте: значения по умолчанию, ошибки по каждой переменной, все ошибки сразу без утечки токена, выход `python -m bot` с кодом 78.
- `test_phrases.py` — валидация пула реплик в `bot/domain/phrases.py`.
- `test_migrations.py` — миграции схемы: новая база, старая база без версии (данные сохраняются), повторный запуск, откат упавшей миграции, отказ при базе новее кода.
- `test_backup.py` — скрипт `scripts/backup_db.py`: копия живой WAL-базы, ротация 7 копий, отказ при отсутствии базы, чтение `DB_PATH` из окружения.
- `test_update_script.py` — сквозной тест `scripts/update.sh` в настоящих git-репозиториях с заглушками `su`/`systemctl`/`journalctl` (на Windows через Git Bash, без bash — пропускается).
- `test_load.py` — нагрузочный тест на 500 одновременных дуэлей с моком `asyncio.sleep`.
- `test_duel_cards.py` — «последнее состояние побеждает» для карточки боя: правки во время идущей сливаются в одну, она показывает текущее состояние, итог боя уходит последним и не сливается, удалённую карточку сообщает только правящий, без наложения каждая правка уходит, карточка рисуется после ожидания слота лимитера, итог ждёт идущую правку боя, итог каждого из N боёв доходит при пропуске правок под лимитером.
- `test_rate_limiter.py` — лимитер на подменённых часах: лимиты бота, чата (с всплеском) и группы, снижение лимита группы на лету, порядок запросов в чате, независимость чатов, исключения (ответы на кнопки, `getUpdates`, `getChat`), очистка простаивающих чатов, подключение лимитера в `create_bot`; реакция на 429: пауза чата и его очереди, пауза для всех при 429 в двух чатах, откат лимита групп до 20 (одна запись), снижение лимита группы до минимума и восстановление не выше 20, одна запись в лог на паузу (метод, `retry_after`, `chat=<id>`), `safe_api` сам о 429 не пишет; N одновременных дуэлей укладываются во все бюджеты, откат до 20/мин действует и на уже ждущие запросы других групп.
